# 第二部分：中文版报告初稿

# 摘要

生成式人工智能降低了获取解释和生成学习内容的门槛，但学习者仍然需要解决三个相互关联的问题：应该学习什么、应该按照什么顺序学习，以及学习计划应该如何根据个人情况发生改变。通用对话式人工智能能够快速生成看似合理的答案和课程安排，但其输出往往缺少稳定的知识依赖结构，也难以持续结合学习者的已有知识、时间限制、学习偏好与实际表现。此外，当系统自动修改学习计划时，如果没有提供清晰的理由和选择权，个性化也可能变成缺少透明度的黑箱决策。

本项目设计并实现了 Pathly，一个基于知识图谱、检索增强生成、学习者画像和多智能体服务的个性化学习系统原型。系统首先将 PDF 课程材料处理为文本块，再抽取概念、先修关系和语义相似关系，形成可查询的知识图谱。知识图谱用于支持学习路径推理，ChromaDB 向量库用于检索相关原始材料，SQLite 用于保存学习者画像。Planning Agent 将自然语言学习目标映射到图谱概念，并结合先修关系、已有知识和每日时间限制生成逐日学习计划。在此基础上，Content、Resource Recommendation 和 Adaptation 服务分别支持内容组织、资源匹配和路径调整建议。交互原型通过学习路径、推荐理由、测验信号和计划版本记录，将后端推理转化为学习者可以理解和控制的体验。

项目采用迭代式设计与技术原型方法，并使用阶段运行时间、知识图谱 precision、recall 和 F1、后端一致性、可复现运行工具及场景化流程检查进行评估。结果表明，项目已经形成可运行的知识图谱工程底座和个性化学习原型，但自动抽取的先修关系质量仍然不足，难度等级分布也存在过度集中的问题。目前的证据能够支持系统架构和设计方向具有可行性，却不能证明其已经提高真实学习效果。项目的主要贡献是提出并实现了一种将结构化知识、原始学习资源、学习者约束和可解释路径调整结合起来的系统方案，同时识别了知识关系质量与真实用户验证是后续发展的关键。

# 1. 引言

## 1.1 研究背景

近年来，大语言模型逐渐被应用于解释概念、回答问题、生成练习和制定学习计划。与传统在线课程相比，生成式人工智能能够根据用户的问题即时调整表达方式，因此具有支持个性化学习的潜力。然而，“能够生成不同的内容”并不等同于“能够提供可靠的个性化学习”。当学习者希望进入一个陌生领域时，困难通常不只在于找不到资料，而在于无法判断概念之间的依赖关系。例如，在理解神经网络训练之前，学习者可能需要先理解神经元、激活函数、前向传播和损失函数。如果系统只根据语言流畅度生成课程安排，就可能遗漏关键先修知识，或把相关但没有先后依赖的概念错误地排列成学习路径。

与此同时，不同学习者的起点和限制并不相同。一个具有 Python 基础但数学信心较低的学习者，可能需要更多直观类比和渐进式公式；另一个数学基础较强但时间有限的学习者，则可能更适合压缩解释并增加实践任务。因此，个性化学习至少需要考虑学习目标、已有知识、每日时间、学习节奏、内容偏好以及学习过程中的表现。如果这些信息只在一次对话中临时出现，系统很难形成稳定、可追踪的学习过程。

自适应学习还涉及透明度和控制权。当系统依据测验成绩或学习者反馈改变路径时，学习者应该知道系统观察到了什么、为什么建议调整，以及这一调整会如何影响原计划。系统如果在后台静默改变课程，可能降低学习者对计划的理解和信任。因此，本项目将“可解释性”和“学习者控制”视为个性化学习体验的一部分，而不是仅在技术完成后增加的界面说明。

## 1.2 设计挑战

本项目关注的核心挑战是：如何把分散的学习材料转化为结构化、可查询的知识基础，并利用这个基础为不同学习者生成具有理由、能够调整且保留用户控制的学习路径。

这一挑战包括四个层面。第一，原始课程材料通常以幻灯片、讲义和论文 PDF 的形式存在，结构和文本质量差异明显。第二，系统不仅要识别材料中的概念，还要区分先修关系和语义相似关系。第三，生成的路径必须结合学习者目标和时间约束，而不能只输出通用课程目录。第四，系统需要把复杂的推理过程转化为学习者能够理解的界面，并允许学习者查看和决定是否接受调整。

## 1.3 项目目标

本项目的总体目标是设计一个由知识图谱驱动的多智能体个性化学习系统，并探索结构化知识、检索、学习者画像和可解释交互如何共同支持学习规划。

具体目标如下：

1. 建立从不同类型 PDF 学习材料中提取概念和关系的知识图谱流水线；
2. 建立分别支持结构查询、文本检索和学习者状态管理的数据基础；
3. 根据自然语言目标、知识依赖、已有知识和时间限制生成逐日学习计划；
4. 设计内容支持、资源推荐和学习路径调整的多智能体服务；
5. 通过技术评测、运行审计和交互场景检查项目的可行性与限制。

## 1.4 研究问题

本项目的主研究问题是：

> 基于知识图谱的多智能体系统如何支持可解释、可调整的个性化学习？

三个子问题分别是：

- RQ1：如何将异构学习材料转化为适合学习路径规划的结构化知识表示？
- RQ2：如何结合学习目标、学习者画像和知识依赖，生成可行且可解释的学习计划？
- RQ3：如何在交互体验中呈现推荐和调整，使学习者理解系统理由并保留控制权？

## 1.5 项目范围与贡献

项目的技术范围包括 PDF 到知识图谱的构建流程、Neo4j/JSON 图查询、ChromaDB 检索、SQLite 学习者画像、Planning Agent 以及支持内容、资源和适应性决策的服务。项目也包含一个前端交互原型，用于呈现 onboarding、路径生成、每日学习、资源推荐、问答、测验和路径调整流程。

本项目目前没有完成正式的大规模用户研究，也没有比较使用系统前后的学习成绩。因此，论文不会声称 Pathly 已经提升了学习效果。项目的贡献主要在三个方面：第一，建立了从学习材料到可查询知识结构的工程流程；第二，提出并实现了 KG、RAG、画像和多智能体的分层架构；第三，探索了如何通过推荐理由、调整确认和版本历史提高个性化学习体验的透明度。

# 2. 背景与文献综述

## 2.1 个性化与自适应学习

个性化学习通常指根据学习者的目标、能力、偏好或限制提供不同的内容和路径；自适应学习更强调系统根据学习过程中的新证据持续改变后续体验。[待补文献：personalised learning 与 adaptive learning 的定义和区别] 两者虽然相关，但并不完全相同。一个系统可以在开始时根据用户偏好生成个性化计划，却不一定会根据后续表现调整；也可以根据答题正确率动态改变难度，却忽视学习者最初的目标与时间限制。

本项目将个性化分为三个层次。第一层是结构个性化，即选择哪些概念以及学习顺序。第二层是呈现个性化，即使用何种解释、案例和资源。第三层是过程个性化，即根据学习者反馈调整后续安排。这个区分直接影响了系统架构：Planning Agent 主要负责结构，Content 和 Resource 服务主要负责呈现，Adaptation 服务主要负责过程调整。

## 2.2 学习者画像

学习者模型用于表示与学习相关的个人特征，例如已有知识、目标、偏好、动机和信心。[待补文献：learner modelling、open learner model] 传统系统可能根据测验表现推断能力，而生成式 AI 系统也可以直接询问学习者的背景和偏好。然而，不论是显式填写还是行为推断，画像都可能不准确。学习者的信心可能随主题变化，偏好也不一定代表最有效的学习方式。

因此，本项目没有把画像视为固定真相，而是把它视为可查看、可修改的规划输入。系统原型允许用户检查学习目标、每日时间、基础、内容偏好和信心。画像用于调整计划和解释方式，但不应在用户不知情的情况下永久定义其能力。这一选择与开放式学习者模型和可纠正 AI 的思想一致。[待补文献]

## 2.3 教育知识图谱

知识图谱通过节点和关系表示领域知识。在教育场景中，节点可以表示概念、主题或资源，关系可以表示先修、相似、从属或资源关联。[待补文献：educational knowledge graphs、prerequisite learning] 与线性课程目录相比，知识图谱能够表示多个可能路径，也能为推荐提供结构化理由。例如，系统可以说明推荐“激活函数”是因为它是理解“前向传播”的先修内容。

但知识图谱的价值取决于节点和关系质量。概念遗漏、名称重复或错误的先修边都会影响路径规划。尤其是 prerequisite 关系，它不是简单的文本相似度：两个概念可以高度相关，却不存在明确的学习顺序。因此，本项目将 topic、prerequisite 和 similarity 分开生成和评估，并保留人工标注评测入口。

## 2.4 大语言模型与检索增强生成

大语言模型具有强大的自然语言生成和概念解释能力，但它们可能生成缺少来源或事实不准确的内容。[待补文献：LLM hallucination in education] RAG 通过先检索相关材料，再让模型基于检索上下文生成内容，可以改善内容与课程材料之间的关联。[待补文献：RAG]

本项目将知识图谱和 RAG 视为互补基础。知识图谱负责回答“概念之间是什么关系”和“学习顺序可能是什么”，向量检索负责回答“哪些原始文本与当前概念相关”。如果只使用 RAG，系统能够找到相似段落，却不一定得到可靠的先修结构；如果只使用 KG，系统能够生成路径，却缺少足够的原始材料支持详细解释。两者结合有助于同时支持规划和内容生成。

## 2.5 多智能体系统

多智能体系统把复杂任务分配给具有不同职责的组件。[待补文献：multi-agent systems and agentic workflows] 在本项目中，多 Agent 的意义不在于增加更多模型名称，而在于划分决策责任。Planning Agent 决定学习结构，Content 服务组织当前内容，Resource Recommendation 服务匹配材料，Adaptation 服务根据学习信号提出修改候选。职责分离使不同模块可以独立测试，也能帮助系统向用户说明某项建议来自哪一类证据。

另一种选择是让一个 LLM 同时读取用户信息、课程材料、测验结果并生成所有内容。该方案实现简单，但难以追踪错误来源。如果学习路径不合理，很难判断问题来自目标解析、概念映射、先修关系还是时间分配。因此，本项目采用结构化模块与 Agent 服务组合，而不是完全自由的单模型工作流。

## 2.6 可解释性与学习者控制

推荐系统中的解释可以帮助用户理解为什么看到某项内容，但解释本身也可能只是表面合理化。[待补文献：explainable recommendation、human agency] 本项目尽量使用可追踪的结构证据，例如先修边、时间限制、画像偏好和测验信号，而不是只生成一句通用的“这是为你推荐的”。

学习路径调整尤其需要用户控制。Pathly 原型不会直接覆盖原计划，而是展示调整前后的差异、判断依据和时间影响，并提供接受、拒绝和修改三个选项。版本历史保留原计划和新计划，使适应过程可以被追踪。

## 2.7 文献导出的设计原则

上述研究形成了本项目的六条设计原则：

1. 在生成内容之前先建立可查询的知识结构；
2. 使用原始学习材料约束和支持生成内容；
3. 将学习者画像视为可修改输入，而不是固定标签；
4. 将规划、内容、资源和适应职责分离；
5. 为推荐和调整提供可以追踪的理由；
6. 路径可以由系统建议，但最终控制权应保留给学习者。

# 3. 方法与过程

## 3.1 总体研究方法

本项目采用迭代式设计和技术原型相结合的方法。研究过程不是先完成全部文献，再一次性实现最终系统，而是在问题定义、技术构建、原型展示和评估之间反复迭代。该方法适合本项目，因为研究目标既包括构建一个可运行系统，也包括探索学习路径应该如何被解释和调整。

项目可以被视为一种 Research through Design 实践：[待补设计研究方法文献] 通过制作知识图谱流水线、Agent 服务和交互原型，项目不仅产生一个作品，也暴露了知识关系质量、数据职责边界和学习者控制等设计问题。技术测试和评测结果随后用于修正系统主张与下一轮设计。

## 3.2 需求与核心场景

系统的核心场景是一名具有部分编程基础、数学信心一般的学习者，希望在七天内理解神经网络基础，每天可投入约 75 至 90 分钟。这个场景要求系统完成以下任务：理解学习目标；判断目标在知识图谱中的位置；识别必要先修知识；跳过学习者已经掌握的内容；把主题分配到有限时间中；提供适合其偏好的解释与资源；在学习表现不足时提出调整。

该场景被选中是因为它覆盖了项目的主要系统关系，同时足够具体，可以用于检查每个界面和服务是否真的支持同一个学习过程。它不是对所有学习者的代表性证明，而是设计和技术原型的验证场景。

## 3.3 系统架构方法

系统被划分为四个主要数据和服务层。[待补图：系统总架构]

第一层是知识构建层，将 PDF 处理为 chunk、topic、prerequisite、similarity 和节点摘要。第二层是数据基础，包括用于结构关系的 JSON/Neo4j、用于文本检索的 ChromaDB，以及用于学习者画像的 SQLite。第三层是 Agent 服务，包括 Planning、Content Context、Resource Recommendation 和 Adaptation Candidate。第四层是交互层，用于呈现路径、每日内容、测验和调整建议。

数据职责被有意分开。Neo4j 只保存领域知识和资源关系，不保存学习者的 mastery、progress、deadline 等动态状态；SQLite 负责学习者画像；ChromaDB 保存 chunk 和 embedding。这一设计降低了不同数据生命周期互相干扰的风险，也使隐私和更新逻辑更容易管理。

## 3.4 知识图谱构建方法

PDF-to-KG 流水线由多个阶段组成。Stage 1 提取和清理文本，并根据文档类型进行自适应分块。Stage 2a 使用 KeyBERT、SentenceTransformer 和 LLM 组合提取主题；Stage 2b 推断先修关系；Stage 2c 计算语义相似边；Stage 3 为节点生成摘要；Stage 4 输出 JSON、GEXF 和可视化图。

混合方案是在规则、嵌入模型和 LLM 之间作出的折中。规则方案成本较低且容易复现，但难以处理复杂语义；完全依赖 LLM 能够提供更灵活的判断，却带来成本、非确定性和解释困难。项目因此使用本地模型生成候选，再在需要时使用 LLM 精修，并为部分步骤保留 fallback。

## 3.5 学习计划生成方法

Planning Agent 将规划任务拆分为多个步骤。Goal Parser 从自然语言中提取目标概念、计划天数、每日时间和其他限制；Topic Mapper 使用名称和语义匹配将目标映射到图谱节点；Path Planner 根据先修关系构建候选学习顺序；Time Allocator 根据主题难度、预计时间和画像中的节奏偏好进行每日分配。最终输出包含每日主题、预计时间、先修桥接、安排理由和可行性警告。

该方法与直接让 LLM 生成计划不同。LLM 可以参与目标理解或语言表达，但核心路径尽量由结构化关系和明确约束产生。这样做不能自动保证计划正确，因为输入图谱仍可能存在错误，但可以帮助开发者和学习者追踪计划来源。

## 3.6 交互原型方法

交互原型围绕完整用户旅程设计，包括 onboarding、目标输入、计划生成、学习路径 dashboard、每日学习、资源、问答、quiz、学习总结和 adaptation proposal。路径同时使用知识关系视图和时间线视图，以支持“为什么学”和“什么时候学”两种理解。

适应界面不是只显示更新后的结果，而是比较原计划和建议计划，列出测验错误、信心和问答等判断依据，并显示时间如何重新分配。用户可以接受、拒绝或修改建议。该交互用于探索可解释适应和学习者控制，而不是证明用户一定会更喜欢这种方式。

## 3.7 评估方法

评估包含四部分。第一，使用人工标注小样本计算 topic、prerequisite 和 similarity 的 precision、recall 与 F1。第二，记录各流水线阶段的运行时间。第三，通过测试、manifest、日志、baseline 和复现脚本检查工程可靠性。第四，使用核心学习场景检查 Planning Agent、RAG、JSON/Neo4j 后端和交互流程是否能够形成一致的端到端体验。

本项目目前没有正式参与者实验，因此界面部分主要采用场景 walkthrough 和功能原型检查。最终报告应将这一点作为研究限制，而不能把设计演示等同于用户可用性或教育效果验证。

# 4. 分析与迭代

## 4.1 迭代一：从 PDF 到结构化知识

项目最初需要解决的问题是如何从课程材料中得到可以用于规划的概念结构。早期处理方式更接近普通文本切分，但 PDF 幻灯片、讲义和论文具有不同的段落特征。固定长度分块可能把一个解释拆成多个部分，也可能把无关页面合并在一起。因此，系统发展出针对 slides、lecture notes 和 paper/book 的自适应分块，并增加清洗和噪声过滤。

仅仅提取关键词并不足以生成学习路径。关键词可以表示文档谈论了什么，却不能说明哪些概念应该先学。项目因此把主题提取、先修关系和相似关系拆成独立阶段。这个决定提高了系统结构的清晰度，也使三类输出可以分别评估。不过，后续结果表明 prerequisite 是最困难的关系类型。语义相关不等于学习依赖，而自动生成的关系可能受到材料表达顺序和 LLM 判断的影响。

这一迭代形成了项目的第一个重要认识：知识图谱不是天然正确的事实层，而是一个需要质量控制的设计材料。图谱可视化能够帮助观察结构，但漂亮的网络图本身不能证明关系适合教育规划。因此，项目增加了人工 gold annotation 和独立质量评测入口。

## 4.2 迭代二：从脚本流水线到可追踪基础设施

早期 KG 流程主要由多个脚本顺序执行。这种方式能够生成结果，但当文档数量增加或某个阶段失败时，难以判断哪些输出仍然有效。如果 Agent 直接读取散落 JSON，也会把底层格式与上层逻辑紧密绑定。

项目随后建立 KG repository、统一配置和设备管理层，并增加 baseline、文档 hash、manifest、阶段日志和 recovery state。每份文档的运行结果被隔离保存，理论上可以在失败后从首个未完成阶段继续，而不需要重新执行全部流程。评测入口也开始固定输入材料、标注文件和输出目录。

这次迭代并不直接增加最终用户可见功能，但它改变了项目对“可信”的理解。学习计划的解释如果建立在无法追踪的流水线输出上，其可信度仍然有限。因此，可审计运行和数据来源成为系统体验的后台条件。

不过，复现检查也暴露了限制。部分阶段受到模型非确定性或环境变化影响，重新运行的 hash 和指标没有完全保持一致；运行时间也会发生变化。因此，当前系统可以称为具有复现工具和结构化证据，但不能宣称所有结果已经稳定复现。

## 4.3 迭代三：从 JSON 到 Neo4j Knowledge Layer

JSON 文件适合快速原型和单次结果检查，但随着全局概念、资源和多种关系增加，查询先修路径、相关资源和邻接关系变得更复杂。项目因此增加 Neo4j 作为图查询后端，同时保留 JSON backend 作为轻量和回退方案。

迁移过程中一个关键决定是限制 Neo4j 的职责。另一种可能方案是把用户画像、学习进度、文本 chunk 和所有状态都放入图数据库，这能够形成一个统一数据入口，但也会混合领域知识、个人数据和大规模文本。项目最终规定 Neo4j 只保存 Concept、Topic、Resource 以及 PREREQUISITE_OF、SIMILAR_TO、BELONGS_TO、HAS_RESOURCE 等结构关系。学习者动态信息继续保存在 SQLite，正文和 embedding 保存在 ChromaDB。

项目通过 repository factory 让 Planning Agent 可以在 JSON 和 Neo4j 之间切换，并验证核心规划输出的一致性。该结果说明上层规划逻辑不必绑定具体存储形式，也为后续扩展提供了空间。但后端一致只证明接口行为相近，不证明底层知识关系本身完全正确。

## 4.4 迭代四：Planning Agent

Planning Agent 是把知识基础转化为用户价值的关键部分。最简单的替代方案是把目标和画像直接交给 LLM，并要求它输出七天课程。这种方法能够快速得到流畅结果，但计划中的主题来源和顺序难以检查。项目因此将规划拆分为目标解析、概念映射、路径搜索和时间分配。

例如，用户输入“我希望在七天内学习神经网络基础，每天 75 分钟，我有 Python 基础但数学信心一般”。系统首先提取目标和约束，再将 Neural Networks 映射到图谱概念。Path Planner 获取相关先修节点，并结合 known topics 过滤已经掌握的内容。Time Allocator 根据主题难度和可用时间生成每天的安排。如果目标在给定时间内不可行，输出应包含 warning，而不是假装所有目标都可以完成。

计划输出不仅包括主题和时间，也包含 prerequisite bridge 和 reason。这些字段使前端能够解释某项内容为什么出现在路径中。结构化输出还允许独立检查每一天是否超过时间限制。当前测试和场景运行说明主链路可以生成逐日计划，JSON 与 Neo4j 后端也能保持核心结果一致。但计划质量仍依赖 topic mapping、先修边和难度估计，因此这些上游问题会传播到最终体验。

## 4.5 迭代五：从计划生成器到学习体验

只输出 JSON 计划不能充分回答设计研究问题，因为学习者最终面对的是界面，而不是后端对象。Pathly 原型因此把计划转化为七天学习路径，并增加每日课程、资源推荐、问答和 quiz。

在 dashboard 中，用户可以在知识关系图和时间线之间切换。知识图帮助用户理解概念依赖，时间线帮助用户理解工作量。点击节点后，系统显示预计时间、掌握度和规划理由。在每日学习中，Content Agent 的角色是根据学习者偏好调整解释顺序，例如先用直观类比，再连接公式和代码；Resource Recommendation 则展示资源类型、预计时间和推荐理由。

这轮设计中最重要的变化发生在 adaptation 流程。自动修改计划虽然操作简单，却可能让学习者失去对学习过程的理解。最终原型将调整设计为建议：当学习者在测验中答错激活函数相关问题、选择较低信心并在问答中反复询问参数影响时，系统建议在反向传播之前增加“梯度直觉补强”，同时压缩后续扩展练习。界面显示判断依据和时间变化，并允许用户接受、拒绝或修改。

版本历史保留原计划 v1 和调整后计划 v2。这使适应不再表现为系统突然改变内容，而成为可以讨论和决定的过程。需要强调的是，这一设计目前通过原型场景展示，尚未通过真实用户研究证明能够提高理解或信任。

## 4.6 评估结果如何影响设计

项目的运行基础已经能够处理多份课程材料，并形成全局知识图谱。当前运行基础设施报告记录约 183 个概念和 178 条边，未检测到重复概念；Neo4j 中也已经包含 Topic、Resource 和相应关系。RAG 验证中已有约 424 个 chunk，Planning 核心场景可以运行，并通过 JSON/Neo4j parity 检查。[最终提交前应从最新 manifest 再确认数字]

但质量评测给出了更谨慎的结论。一组固定小样本评测曾得到 topic precision 约 0.333、recall 约 0.5、F1 约 0.4；similarity precision 约 0.5、recall 约 0.333、F1 约 0.4；prerequisite precision、recall 和 F1 均为 0。该结果受小样本和运行变化影响，不能用于概括所有材料，但它清楚说明 prerequisite 抽取尚不能被视为可靠。

运行审计还发现 difficulty level 大量集中在 level 2。校准工具可以生成单独的 calibrated graph，但原始难度预测仍需要改进。设备验证显示机器存在 NVIDIA GPU，但当前 Python 环境使用 CPU 版 PyTorch，因此系统只验证了“请求 GPU 失败后稳定回退 CPU”，没有证据支持真实 CUDA 加速。

这些发现改变了最终项目表述。项目不再把图谱规模或功能数量作为成功的主要证明，而是把成果描述为“具有工程化 KG 底座的个性化学习原型”。最终设计保留解释和人工控制，也为未来加入关系校验提供空间。

## 4.7 被拒绝或调整的方案

项目中的主要取舍如下：

- 固定长度分块被调整为适应不同文档类型的分块方式；
- 单一关键词提取被调整为本地模型与 LLM 结合的混合流程；
- 直接由 LLM 自由生成完整路径被调整为 KG 关系与显式约束驱动的规划；
- Agent 直接解析原始 JSON 被 repository 抽象层取代；
- 将所有数据写入 Neo4j 的方案被分层存储取代；
- 系统静默修改学习计划被可解释、可拒绝的调整建议取代；
- “已经完成 GPU 迁移”的表述因缺少真实 CUDA 证据而被拒绝；
- “系统提升了学习效果”的表述因缺少用户实验而被拒绝。

这些被拒绝的方案不是项目失败，而是设计推理的重要证据。它们说明最终系统由技术结果和限制共同塑造。

# 5. 成果

## 5.1 最终设计方案

Pathly 的最终设计方案由结构化知识、材料检索、学习者画像、Agent 服务和可解释交互五个部分组成。学习材料通过流水线转化为概念和关系；Neo4j/JSON 提供图查询；ChromaDB 提供原文 chunk 检索；SQLite 保存画像；Planning Agent 生成学习结构，其他服务支持内容、资源和调整；前端把这些能力组织为连续的学习旅程。

## 5.2 技术成果

项目已经形成较完整的 PDF-to-KG 工程链路，包括自适应分块、主题提取、先修与相似关系、节点摘要、图谱输出、批量运行、日志、baseline、评测和 Neo4j 导入。RAG 和 learner profile 也已具备可运行的数据基础。Planning Agent 能够从目标和画像生成逐日计划，并支持不同图后端。

Content Context、Resource Recommendation 和 Adaptation Candidate 已形成服务或场景能力，但它们仍处在原型到早期工程化阶段。当前系统能够演示这些部分如何连接，却没有完成长期学习数据回写、真实内容质量评审和多用户运行验证。

## 5.3 设计成果

交互原型形成了从目标输入到路径调整的完整叙事。其主要设计成果包括：使用图谱和时间线表达路径；为计划节点和资源显示推荐理由；根据画像调整内容组织；同时使用答题表现和信心作为调整线索；在修改计划之前展示依据；允许用户接受、拒绝或修改；保存路径版本历史。

这些成果回应了项目对 explainability 和 learner agency 的关注。系统没有把解释限制为一段自动生成文案，而是尽量将其连接到先修关系、画像、时间和学习信号。

## 5.4 项目目标完成度

从工程角度看，PDF 到知识图谱、数据基础和 Planning 主链路已经实现。从设计原型角度看，内容、资源、反馈和适应流程已经被整合为可演示体验。从研究验证角度看，当前完成了技术评测和场景检查，但没有完成正式用户研究或学习效果实验。因此，本项目实现了系统和设计可行性目标，只部分实现了质量验证目标，尚未实现教育效果验证目标。

# 6. 讨论

## 6.1 对研究问题的回答

对于 RQ1，本项目表明异构 PDF 可以通过自适应分块、主题抽取和关系推断转化为可查询知识图谱。分阶段流水线和 Neo4j 数据层使知识能够被 Planning 和其他服务复用。不过，自动构建不代表关系可靠，尤其是先修关系仍需要更强模型、人工校验或课程专家参与。

对于 RQ2，项目表明自然语言目标、学习者画像、图谱关系和时间约束可以通过模块化规划流程组合成逐日学习计划。相比完全自由的 LLM 输出，结构化规划更容易检查和解释。但其最终质量取决于上游图谱和难度信息，因此可解释性使问题更可见，却不会自动消除错误。

对于 RQ3，Pathly 原型展示了一种可解释适应方式：把推荐理由、行为证据、路径差异和用户决定放在同一个流程中。用户可以理解系统为何建议改变，也可以保留原计划。当前设计回答了“可以如何呈现”的问题，但尚未回答真实学习者是否能够理解、信任或愿意使用这些功能。

## 6.2 KG 与 RAG 的互补价值

项目最重要的系统认识之一是 KG 和 RAG 不应被视为互相替代的技术。KG 提供概念结构和路径理由，RAG 提供与课程材料相关的正文。如果只使用向量相似度，系统可能找到大量相关材料，却无法可靠排序；如果只使用知识图谱，系统能够生成骨架，却可能缺少足够内容。两者组合可以让 Planning 使用结构，让 Content 使用材料。

## 6.3 多智能体分工的意义

多 Agent 的价值取决于职责是否清晰。如果多个 Agent 只是分别调用同一个模型并产生难以追踪的文本，系统复杂度会增加而透明度不会改善。本项目的 Agent 划分以数据和决策类型为基础：Planning 负责结构，Content 负责呈现，Resource 负责匹配，Adaptation 负责调整候选。该分工使每个服务能够使用不同证据，并为前端解释提供来源。

## 6.4 设计影响

本项目说明，个性化学习不应该只表现为“系统知道你的名字”或“使用你喜欢的语气”。更有意义的个性化发生在目标选择、知识顺序、时间负担、解释方式和调整过程。与此同时，个性化程度越高，系统越需要显示它对用户作出了哪些假设，并允许用户修改这些假设。

适应性也不应该等同于自动化程度。Pathly 的调整提案说明，系统可以主动发现问题，但不必替用户作出所有决定。对于目标明确的成年学习者，保留选择权可能比静默优化更符合学习自主性。[待通过用户研究验证]

## 6.5 技术与研究限制

第一，当前知识图谱质量有限。小样本评测中的 prerequisite 结果较弱，可能直接影响路径合理性。第二，gold annotation 规模较小，且部分模型输出具有非确定性，指标不能代表所有课程材料。第三，难度等级分布过于集中，使时间分配缺少精细区分。第四，虽然系统已经提供 GPU 优先和 CPU 回退机制，但当前环境没有完成真实 CUDA 运行验证。

第五，Content 和 Adaptation 仍主要是原型服务，尚未对生成内容的正确性、教学适切性和长期调整稳定性进行系统评估。第六，项目没有正式用户研究，因此无法证明界面可用性、解释是否被理解，或系统是否改善学习表现。第七，当前核心场景集中在计算机科学和机器学习材料，不能直接推广到所有学科。

## 6.6 伦理、隐私与风险

学习者画像可能包含信心、焦虑、兴趣和能力判断。这些信息具有敏感性，系统需要明确采集目的、保存方式和删除机制。系统从行为推断出的画像也可能错误，并形成自我强化：如果系统认为用户数学能力弱，可能不断降低内容难度，从而限制其发展。因此，画像应可见、可修改，并尽量保留证据来源。

生成内容和自动知识关系也可能产生错误。教育场景中的错误不只是一般事实问题，还可能影响后续学习路径。因此，系统需要来源展示、低置信度提示和人工校验机制。课程 PDF 的版权和上传权限也应在真实部署中处理。

## 6.7 后续工作

后续工作的第一优先级是改进和验证 prerequisite 关系。可以扩大人工标注集、引入课程专家评审、比较不同模型和提示方法，并允许管理员在图谱中修改边。第二，应改进难度与学习时间估计，使 Planning Agent 的分配更加可信。第三，应完成真实的学习反馈闭环，让 quiz、问答和自我反馈以透明方式更新画像并产生调整候选。

在设计研究方面，应首先开展小规模可用性测试，观察用户是否理解路径图、推荐理由和调整提案，然后开展纵向研究，比较 KG 约束计划与纯 LLM 计划在完成率、理解、信任和感知控制方面的差异。只有在这些研究完成后，才能进一步讨论系统是否改善学习效果。

# 7. 结论

本项目探索了基于知识图谱的多智能体系统如何支持可解释、可调整的个性化学习。最终系统将 PDF 学习材料转化为概念和关系，使用 Neo4j/JSON 支持结构查询，使用 ChromaDB 支持原始材料检索，使用 SQLite 管理学习者画像，并通过 Planning Agent 将目标、先修关系和时间约束组合成逐日计划。Content、Resource 和 Adaptation 服务进一步展示了系统如何从计划扩展到连续学习体验。

项目表明，知识图谱可以为学习路径提供结构和解释，RAG 可以为内容提供材料依据，学习者画像可以影响时间和呈现方式，多 Agent 分工可以使不同决策更容易追踪。Pathly 原型还表明，适应性不必意味着系统静默控制；通过展示依据、比较版本并让用户接受或拒绝，路径调整可以成为学习者参与的过程。

同时，项目也揭示了这一方向的关键限制。自动先修关系的质量尚不可靠，难度校准仍需改进，部分结果存在运行变化，真实 CUDA 尚未验证，Content 和 Adaptation 尚未完成长期闭环，并且缺少正式用户研究。因此，本项目证明的是一种系统架构和交互设计的可行性，而不是已经证明学习效果提升。

总体而言，本项目的价值不仅在于实现了若干 AI 模块，而在于建立了一条从学习材料、知识结构、个人约束到可解释学习决策的连接路径。未来工作的重点应从继续增加功能，转向提高知识关系质量、验证解释是否有效、保护学习者数据，并通过真实学习过程检验系统的教育价值。
